# 移动端 MVP 实施计划

## 当前判断

CY-Booking 的主力体验应该放在移动端。Web 端可以保留为后续后台、解析调试台或批量导入工具，但不再作为主 MVP 打磨对象。

原因：

- 微信、支付宝、截图和账单文件都主要发生在手机端。
- 记账、补录、改分类是高频碎片动作，更适合移动端。
- 本地优先和隐私控制在移动端更容易建立信任。

## MVP 主线

```txt
选择账单 CSV
-> 端侧读取文件
-> packages/core 解析为交易
-> 自动分类与去重
-> 移动端预览确认
-> 写入本地账本状态
-> 后续接 SQLite 持久化
```

## 当前阶段目标

第一阶段先做到“手机端真实导入闭环”：

- 移动端复用 `packages/core` 的交易模型。
- 支持选择 CSV 文件。
- 支持微信/支付宝样例账单。
- 导入后进入待确认列表。
- 重复交易不入账。
- 确认后写入当前本地账本状态。
- 首页和统计页实时更新。

## 后续阶段

### 阶段二：本地持久化

- 接入 Expo SQLite 或 WatermelonDB。
- 保存交易、分类、账户和导入历史。
- App 重启后保留数据。

### 阶段三：导入能力增强

- 增加 XLSX。
- 增加 PDF 文本型账单。
- 增加截图 OCR 单笔识别。
- 增加导入异常页。

### 阶段四：云备份

- NestJS 用户系统。
- 云备份快照。
- 换机恢复。
- 会员能力入口。

## 暂缓内容

- Web 管理台深度打磨。
- 多端实时同步。
- 复杂预算系统。
- 银行 PDF 全覆盖。
- 微信/支付宝自动同步。
